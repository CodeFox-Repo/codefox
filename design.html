What actually happens

Four steps, none of them a mock.

01 · Scaffold

A directory, not a plan

The starter template is cloned once and copied per project. Your project has a real package.json before the model writes a single line.

git clone --depth 1 template
cp -r template .codefox/projects/<id>
ln -s cache/node_modules ./node_modules
02 · Agent

Claude Code, embedded

Not a homegrown loop. The real agent runs through the AI SDK harness with its own read, edit, search and shell tools.

read   src/app/page.tsx
bash   ls src/components/ui
read   src/components/mode-toggle.tsx
edit   src/app/page.tsx
03 · Sandbox

Your machine is the sandbox

A local sandbox provider gives the agent a scoped directory, real child processes and a localhost port — so it can use the Claude CLI you are already signed into.

provider  codefox-local
cwd       .codefox/projects/<id>
bridge    ws://127.0.0.1:<port>
auth      your existing login

Read this before you star it

What it does not do yet.

Every generator demo looks the same. Here is the part the demo leaves out.

› The sandbox is not isolation by design

The agent runs with the backend process's privileges in a scoped directory. That is the trade for using your own local login. Swap in a network sandbox provider for anything untrusted — the interface is the same.

› Projects share one node_modules known

Every project comes from the same template, so they symlink a single install. That stops being true the moment the agent is allowed to add a dependency.

› One template, one stack roadmap

Next.js 15 + Tailwind + shadcn is the only starter today. The scaffolder takes a git URL, so a second template is configuration rather than code — but nothing selects between them yet.

› A fresh install has nothing to show you empty state

Projects created before the scaffolder existed have no directory, so the preview says so instead of spinning forever.
